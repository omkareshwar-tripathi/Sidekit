## LinkedIn
I renamed my macOS app today — and the riskiest part wasn't the name.

I'm building Sidekit: an always-on-top, fully on-device desktop surface — dictation, a temporary file shelf, and a webcam mirror, all in one panel. It started life as a dictation tool called "SpeakType." Today it became what it actually is: SpeakType is now just one feature *inside* Sidekit.

Renaming a shipped app sounds like find-and-replace. It isn't.

macOS ties every permission a user grants — microphone, camera, accessibility — to the app's bundle identifier, not its display name. If I'd "cleaned up" that ID to match the new brand, every existing user would be silently de-authorized and forced to re-grant all three permissions on next launch. Invisible to me in testing; infuriating to them.

So the rule I followed: rename everything the user sees — app name, window title, menus, the .app itself — and never touch the identifier underneath. The brand is cosmetic. The identity is load-bearing.

Now into the final pre-ship test pass before notarizing. Onward.
